# ADR-0008: Testing strategy

- Status: Accepted (2026-11-14)
- Deciders: qa-senior

## Decision
Tests are written with the code (TDD), prioritised by "what fails silently":
1. **Scientific correctness (pytest)**: DEM↔ortho alignment with control points (< 1 px), nodata handling, slope against analytic surfaces (plane 0°, 45° ramp, paraboloid), projection scale, DEM slope vs Perseverance measured tilt.
2. **Parity Python↔TS**: golden fixtures generated by Python, consumed by Vitest (bilinear sampling, pixel↔world↔lat/lon, planner results, observation builder).
3. **Planner golden cases**: flat, wall, ramp above limit (explicit "no route"), start inside obstacle, ties.
4. **Learning**: seeded determinism; trained agent beats random; PPO success/cost thresholds on unseen scenarios.
5. **E2E (Playwright)** against the deployed preview: WebGL via SwiftShader, `window.__marsx.ready`, non-blank canvas, zero console/network errors, route flow, layer switching; screenshots at 1440 and 390, light and dark, reviewed by a person. FPS measured on real GPUs only.
6. **Demo readiness**: offline local build + 60–90 s backup video, deterministic demo seed, feature freeze 16:00 on Sunday.

Tests never depend on the full 9 GB sources: synthetic rasters and small committed fixtures only.
